# 智能体评测 2026-10-07

30 条问句，跑的是站内真实链路：浏览器里已登录的会话 → `POST /app/ai/chat` → 模型带工具查库 → 回答。
逐条原文见 [原始输出-2026-10-07.md](原始输出-2026-10-07.md)。

## 怎么跑

评测脚本在 `面向用户/public/agent-eval.js`，放这儿是因为它要用用户端已登录的 token：`/app/ai/chat` 要登录态才给查场次和座位，token 只在页面里取，不落终端也不落代码。

打开 `http://localhost:8080` 登录后，控制台执行：

```js
document.head.appendChild(Object.assign(document.createElement('script'), {src: '/agent-eval.js'}))
await AgentEval.runAll()   // 30 条顺序跑，中途能看 AgentEval.state
AgentEval.report()         // Markdown，直接贴回这份文档
```

单条重跑用 `AgentEval.runOne('C5')`，跑前 `AgentEval.clear()` 会清空已有结果。

## 判分口径

- **规则口径**：判分条件全部对着 `AiAssistantService.systemPrompt()` 里的规则写，不另立标准。要调工具就查 `steps`，不许编数字就核 `must`，不许替用户下单就查 `mustNot`，行列 +1 就看正文有没有「0 排」。
- **事实口径**：`seat_summary` 类用例不比对文案，直接 `POST /app/showtimes/getById/{id}` 拿服务端解析出来的座位矩阵，把正文里的「X排Y座」折回 0 下标格子，要求那个格子的值真的是 0（可售）；「还剩 N 个空位」的 N 要和矩阵里 0 的个数对上。
- **影片口径**：正文里出现的片名必须在库里那 21 部里，问句里自带的片名不算幻觉。
- **草稿口径**：`draft.seats` 的个数要等于正文言明的张数，`total` 要等于 `unitPrice × 座位数`，`confirmToken` 必须存在且不能出现在正文里。
- 影院排片数、最低票价、排片日期区间这几项来自当次库查询：`cinema_id=1` 13 场、最低 12.00 元（5 场）、排片落在 2023-12-31 ~ 2024-01-17。

## 三条不过的定性

**C3「新乡万达影城一共有几场排片」** —— 判分器错，不是智能体错。它调了两次 `list_cinemas`，报「13 场」；`list_cinemas` 的返回里本来就带每家影院的场次数，13 也和库里的 `cinema_id=1` 一致。口径已经改成「`find_showtimes` 或 `list_cinemas` 都算，正文必须出现 13」。这条不需要重跑，存下来的回答按新口径就是过的。

**C5「最便宜的场次多少钱」** —— 真缺陷。`find_showtimes` 的 `date` 是可选项，模型按 system prompt 里那句「今天日期 2026-10-07」自己填了进去，库里排片全落在 2023-12-31 ~ 2024-01-17，查回空集就答「查不到场次数据，无法提供价格」。库里最低价其实是 12.00 元（5 场）。B4 是同一个根因，只是那条口径允许答「查不到」，所以判过了 —— 判过不等于没问题。

**D5「哪个场次人最少」** —— 真缺陷。它只调了 `list_movies`，然后回一句「请告诉我您想看的电影名称」，把定参数的活推回给用户。规则 6 为了防止绕圈写了「最多看 3 个场次就必须给结论」，模型宁可反问也不去做那个比较 —— 防绕圈的约束被当成了不干事的理由。

## 已经改了什么

system prompt 从 6 条加到 8 条，针对上面两个真缺陷：

- 规则 6 补一句：跨场次比较（哪个场次人最少、最便宜的场次）先用 `find_showtimes` 拿清单，在这 3 个场次的预算内比出结论，别躲开比较。
- 新规则 7：`date` 这类筛选条件是可选的，用户没给日期就别自己填今天的日期去查；查出空集先把可选条件去掉重查一次再回答没有，空结果先怀疑自己加的条件。
- 新规则 8：能自己定默认值就直接查完给结论，只有缺了没法默认的关键信息才反问。

复跑 B4 / C3 / C5 / D5，再加一条 D2 当对照（看新规则有没有把原本正常的荐座改坏）。

> 复跑结果：待补。重启后端会让用户端的登录态失效（axios 拦截器收到 501 会清 `localStorage` 并跳 `/login`），这一轮要重新登录才能跑。

## 第一轮为什么不能用

第一轮 17/30，但其中 19 条走的是规则兜底 —— 数字没意义。原因是这家提供方的限流不是 429，而是 **HTTP 400 + code -20048「请求过于频繁」**，`LlmClient` 把它当普通调用失败抛了，整条链路就退到 `RuleAssistant`。

评测脚本侧的处置：每条之间隔 3.5 s，命中限流标记（正文开头那句「模型这次没叫通」）就等 8 s 重试一次。第二轮重试 0 条、重试后仍被限流 0 条，30 条里 29 条真走模型。产品侧的重试还没做 —— 这个退避应该在 `LlmClient` 里做，不该只让评测脚本绕过去。

## 兜底路径查出来的四处

第二轮只有 F3 一条退到兜底：模型绕满 5 轮没收口，`AiAssistantService` 直接查库拼了个结论顶上，没丢下一句「你问得太粗」，这个兜底是有效的。顺带把兜底本身的四处毛病定位清楚了（`RuleAssistant.java`）：

1. `showtimes()` 分支不看页面上下文里的 `showtimeId`，用户就在某一场页面上问，它照样打印「查到 21 场」全量清单（F3 那条 668 字就是它）。
2. 关键词覆盖不够：seats 分支要的是「几个人」，「我们6个人能坐一起吗」这种说法一个都命中不了，会掉到最后的帮助文案。
3. draft 分支只认「下单/买/订/就这个/确认」，「重新出一份草稿」里的「草稿」不认。
4. 帮助文案写着「当前后端没配 ai.api-key，走的是关键词兜底」，而实际现在 key 是配好的、退兜底是因为模型没叫通或者绕满轮次，这句在误导用户。

## 已知遗留

- 判分口径这轮修了 5 处：A4 问句自带的片名不能算幻觉、B3 接受 `list_cinemas`、B4 认「暂无」、C2 的「1月3号」会落到 2026 年所以问句写全日期、C3 见上。都是**测试写错、智能体没错**，改的是测试。
- 站里种子数据的排片日期都落在过去，任何按「今天」过滤的问法都会空。C5/B4 是这个问题在模型侧的表现，不是模型独有的毛病。
- 「120 字以内」和列表式回答的冲突，要么改成「清单类不计字数」，要么把规则拆成「正文 120 字、清单另算」。
- 草稿用例的凭证只在浏览器侧，评测断言里包括「正文不许出现凭证」，这条一直是绿的。
