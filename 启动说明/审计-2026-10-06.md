### 403 那两条的判定依据（一次讲清，省得来回猜）

`commons/src/main/resources/com/saodi/mapper/PermissionMapper.xml` 里权限判定只有一句：

```sql
SELECT count(*) b FROM role_permission
JOIN permission ON role_permission.permission_id = permission.id
JOIN cinema_user ON cinema_user.role = role_permission.role_id
WHERE cinema_user.account = #{account}
  AND (#{url} = permission.url OR #{url} LIKE CONCAT(permission.url,'/%'))
```

匹配不到就 `count=0` → `LoginInterceptor.java:74` 回 `code:510 权限不足` → `main.js:59` `router.push({name:'403'})`。
注意用的是 `permission.url,'/%'`（带斜杠），所以 `/movie` 这条权限**盖不住** `/movie-cinema-mapping/update/5`，
而库里根本没有 `/movie-cinema-mapping` 这一行 —— 两个角色都进不去。
顺带一提：`Check` 里是 `JOIN cinema_user ON cinema_user.role = role_permission.role_id`，所以 `role` 为 NULL 的管理员永远 count=0 → 干什么都 403。
实测 account=10077（id=6）的 `role` 就是 NULL（它同时 `status=0`，登录回 504 该账号被禁用，所以这条暂时踩不到，但把 status 打开就是）。13 个管理员里只有 10 个启用：**5 个 1001 + 5 个 1002**，另外 2 个 1001 被禁用、1 个无角色被禁用。也就是说「点排片表进 403」现在影响的是 5 个能登录的账号。

### ⓪ 先报一条审计当时没抓到的、而且级别最高的

**`spring.redis.password` 和本机 Redis 对不上 —— 这不是"某个功能坏了"，是后台全军覆没 + 用户端后端起不来。**

本机 redis 的 `requirepass` 是空的（`redis-cli CONFIG GET requirepass` 返回空，`redis.windows.conf:503` 那行本来就注释着），
而 `manager/application.yml` 和 `app/application.yml` 都写死了 `password: 123456`。Lettuce 照样发 `AUTH`，Redis 回：

```
io.lettuce.core.RedisCommandExecutionException: ERR Client sent AUTH, but no password is set
```

两个后果，都不是同一回事：

- **manager**：`LoginInterceptor.java` 里那句 `redisTemplate.opsForValue().get(token)` 冒泡成 **HTTP 500**，
  于是**只要带 token 的请求全部"服务器内部错误"**。审计里第 7 条我归因给"`main.js` 没 `localStorage.clear()` 所以来回弹登录页"——
  那个是真，但**当时你在后台看到"每个菜单都点不动"的直接原因是这个 500**，不是会话过期。这一条要纠正。
- **app**：`app/config/RedisConfig.java:14` 有个 `RedisMessageListenerContainer`（监听 `__keyevent@0__:expired` 用来超时释放未支付票），
  它在容器启动阶段就要连 Redis → **`Application run failed`，:81 根本起不来**。我 12:59 重启它的时候复现了：
  启动 43 秒后 `listenerContainer` 启动失败，进程退出码 1。之前那次能跑，是因为老进程的连接是在 Redis 改回无密码**之前**建立的，
  Lettuce 不会每条命令重新 AUTH，所以一直没露馅——直到进程重启。

改法（两处 yml 同一行）：`password: ${REDIS_PASSWORD:}` —— 默认不带密码，跟本机实际一致；哪天给 Redis 设了口令，
`set REDIS_PASSWORD=xxx` 就行，不用再改文件。同时给拦截器和登录接口包了兜底：
**Redis 读失败 = 按未登录处理（501，前端跳登录页）**，**写失败 = `ERROR(517,"会话存储(Redis)不可用…")`**，都不再是裸 500。

实测（重启后）：

| 打的是哪个 | 修复前 | 修复后 |
|---|---|---|
| `POST /cinema/getByPage` + 任意假 token | `{"code":500,"msg":"服务器内部错误"}` | `{"code":501,"msg":"登录验证失败"}`，日志 `登录拦截：token=有，会话命中=false` |
| app 进程能不能起来 | `Started` 之后再无日志，`BUILD FAILURE`，81 不监听 | `Started AppStart in 43.245 seconds`，`TCP 0.0.0.0:81 LISTENING` |
| 两边日志里的 Redis 异常计数 | 一堆 | `grep -c "RedisConnectionException"` 加上 `grep -c "Client sent AUTH"` = **0** |
