# 码上影院（Movie Ticketing System）

一套在线购票系统：SpringBoot 多模块后端 + 用户端 / 管理端两个 Vue3 前端，覆盖影院、影厅、场次、在线选座购票与后台多角色权限管理，并带一个基于 tool-calling 的购票智能体。

技术栈：SpringBoot 2.7.3 / Java 8 / MyBatis-Plus / MySQL / Redis / Vue 3 / Element Plus / 七牛对象存储。

各模块的可用性审计与改动记录见 `启动说明/审计-2026-10-06.md`。

## 架构

```
cinema-ticket-system/
├─ 后端java代码/             Maven 多模块（SpringBoot 2.7.3 / Java 8 / MyBatis-Plus）
│  ├─ commons/             实体、Mapper、Service、工具、全局异常、七牛配置   138 个 .java
│  ├─ ai-agent/     [2026] LLM 客户端 + tool-calling 循环 + 规则兜底          20 个 .java
│  ├─ app/                 面向用户端 API        :81  context-path /app      41 个 .java
│  └─ manager/             面向管理端 API        :80  context-path /         32 个 .java
├─ 面向用户/                Vue 3 + Element Plus 2.4  开发端口 8080           17 个 .vue
├─ 面向管理员前端页面/       Vue 3 + Element Plus 1.0  开发端口 8081           45 个 .vue
└─ sql/                    建库脚本与带日期后缀的增量迁移
```

数据层：MySQL 库名 `theater`（28 张表）+ Redis（管理端会话存储、未支付订单的 key 过期监听）。

规模：Java 14,295 行（231 文件），Vue 16,891 行（62 文件）。

**认证是两套**：管理端 = JWT 当 key 存 Redis、30 分钟滑动过期；用户端 = 纯 JWT 无状态校验。

## 核心特性

### ① 购票智能体 `ai-agent`（20 类 / 2,288 行）

用户端右下角一个浮窗，自然语言 → 结构化下单。

**为什么加这个**：Agent 热是入口，但真正让我决定动手的是这个场景的任务形状——用户实际要问的是"周六晚上在附近看一场还能选到好位置的片子"，这是一个要跨影片、影院、场次、座位四类数据做检索和取舍的**复合查询**。用传统 UI 表达它，得在筛选页堆一串互相牵动的下拉框，而且用户往往要到选座那一步才发现场次不对。自然语言 + 工具调用在这里是一条明显更短的路。所以这不是"给系统套个大模型"，是"这个需求本来就该用工具调用来解"。

- **不是 prompt 塞满上下文的做法**：模型只拿到 6 个工具的 JSON Schema，自己决定调用哪个 —— `list_movies` / `list_cinemas` / `find_showtimes` / `seat_summary` / `draft_order` / `hot_now`。循环最多 5 轮（`max-tool-rounds`），每轮把工具结果回灌。
- **工具直接打自己的 Service，不走 HTTP**，避免"AI 通过公网接口绕权限"这类问题。
- **兜底不是装饰**：三种情况都会降级到 `RuleAssistant` —— 没配 API key、模型侧限流/超时、或者一轮里绕满 `max-tool-rounds` 还没收口。它按关键词判意图、从中文数字里抽槽位，调的是**同一批工具 bean**，所以两条路径共用一套座位合法性判断，不会出现"兜底买得到一个模型买不到的座位"。这条路径单独实测过，不是理论上可用。
- **模型无关**：`ai.base-url` / `ai.model` 是配置项，`ai.api-key` 支持环境变量注入；接口按 OpenAI 兼容的 `/v1/chat/completions` 实现，换模型只改两行配置。不绑死某个 provider。
- **下单只到"草稿"**：智能体永远不直接扣库存，产出一张草稿单，跳回选座页把座位勾好，由人点最后那一下。这是产品决策，不是技术限制。
- **带一个 33 条问句的评测集**：覆盖查片/热度/查影院/查场次/座位/草稿/指代/边界八类，跑的是站内真实链路（登录会话 → `/app/ai/chat` → 模型带工具查库）。判分口径直接对着 system prompt 里那 9 条规则写；座位类不比对文案，而是拿服务端解析出的座位矩阵核正文里的排座和空位数，热度类核的是当前这批快照里的片名。一次全量同时出通过率、走模型/退兜底条数、平均耗时、事实核对失败数。口径正确且环境干净的那一轮（第七轮，30 条口径）是 28/30；扩到 33 条之后的复跑还没做，读数和逐条原文见 `智能体评测/`。

### ② 经营看板 `/dashboard`

后台首页从静态占位改成真实聚合查询。口径上做了两件容易做错的事：用 `LEFT JOIN` 保证"零票场次"也出现在结果里（否则"售出 0"和"没数据"长得一样），并单独统计了异常场次体检数。

### ③ 影评 / 想看社区功能

表结构迁移 + app 侧接口 + 用户端 `movie.vue` 影区块 + 后台审核/删除。座位状态做了一次值域拆分：**"损坏"不再等于"已售"**，这是原来数据模型里混在一起的两件事。

### ④ 外部热度榜：快照表，不是实时穿透

站内影视数据是 2023 年那一批，`release_time` 最晚停在 2024-02-08，库里最早的排片也是 2023-12-31 ——「最近什么在映、谁最热」这种问题只能答出一份两年前的榜单，而且数字看着真、用户没法怀疑。加了一条外部数据链路：

- **抓**：`DoubanHotClient` 打豆瓣的 `search_subjects`，一次抓一次写成一个批次（`batch_id` 带毫秒，同秒两次刷新不会撞成一批），表里只留最近 10 批。抓失败时**一行都不写**，旧批次原样还在，于是不会出现「榜单看着是今天的，其实是上次没抓成的」。
- **读**：首页右侧和智能体的 `hot_now` 都只读库里最近一批快照，没有任何一条用户请求实时打到外部源；抓取时间和来源跟着榜单一起显示，快照为空时工具直接说「外部源这次没通」，并禁止回退到站内的 `want_number` 充数——那个数是 2024 年存的一版。`/hot/**` 在登录拦截后面，所以刷新不是谁都能拿来打外部接口的开放代理。
- **落地**：`POST /app/hot/promote` 才把榜单前几部站内还没有的片补成影片、并排出未来十天的场次。这一步是单独点出来的动作，不跟着刷新自动跑——榜单天天变，而排片表是被人拿去卖票的。补进来的片只写榜单真给的片名/评分/海报，时长、地区、上映日期、想看数留空，不编。
- 首页「正在热映」的排序口径跟着改了：原来只看 `release_time` 已过再按一个写死的票房数排，现在优先排本站未来真排着场的片。

## 安全与可用性修复

完整证据在 `启动说明/审计-2026-10-06.md`，每条都标了是浏览器实测、curl 打真实服务、还是源码那一行。这里只列结论：

| 级别 | 问题 | 修法 |
|---|---|---|
| 严重 | `spring.redis.password` 写了实际不存在的口令 → 管理端**每一个**登录后的请求 500，用户端后端 `:81` 直接起不来 | 改 `${REDIS_PASSWORD:}`，拦截器读会话失败按"未登录"处理而不是抛穿 |
| 严重 | 后台登录密码校验被写成恒真 → 任意密码可进管理端 | 恢复 BCrypt 校验 |
| 严重 | 拦截器 `excludePathPatterns("/cinema/**")` 匿名放行整条业务线（含删除、改影院） | 收回到只有登录与验证码两个接口 |
| 严重 | 七牛 AK/SK 明文写在 5 个 Java 文件里 | 抽 `QiniuConfig` + 环境变量，未配置时上传接口返回 511 |
| 高 | 权限 SQL 字符串拼接（注入面）、`'/%'` 前缀匹配导致子路径越权 | 参数化 + 修正匹配逻辑，用拦截器同一条 SQL 验证 18/18 通过 |
| 高 | app 侧按 id 查他人订单（IDOR）、改密码接口"假成功"且把密码哈希返回给前端 | 归属校验 + 明确错误码 506/509 |
| 中 | 角色管理页的删除/批量删除是**前端假按钮**（后端根本没有接口） | 补 `DELETE /charact/del/{id}` + `POST /charact/delBatch`，并接上前端 |

审计文档里还有一节 **「我推翻掉的误报」** —— 有几个看起来像 bug 的东西查下来是正常的，我把它们单独列出来，免得下一个人去"修"没坏的地方。

## 快速开始

### 环境

JDK 8、Maven 3.9、MySQL 5.7+、Redis、Node 16+。

### 1. 建库

```sql
CREATE DATABASE theater DEFAULT CHARSET utf8mb4;
```
导入 `sql/all.sql`（演示数据），再按需执行 `sql/` 下带日期后缀的迁移脚本。

> `all.sql` 里**不含任何账号数据**：原始 dump 里有 29 行用户/管理员账号及其密码哈希，提交前已删除这些行。所以初始状态没有可登录账号，请这样获得一个：
> 1. 打开用户端注册一个普通账号；
> 2. 在库里给它管理员角色：`UPDATE cinema_user SET role='1002' WHERE account='你的账号';`
> 3. 管理端登录用这个账号。
> `1002` 是超级管理员角色，`1001` 是普通管理员，可见菜单差异见 `charact` / `role_menu` 表。

### 2. 后端

```bat
set JAVA_HOME=<你的 JDK8 路径>
cd 后端java代码
mvn -B install -DskipTests
mvn -B -pl manager spring-boot:run -Dspring-boot.run.jvmArguments="-Dfile.encoding=UTF-8"
mvn -B -pl app     spring-boot:run -Dspring-boot.run.jvmArguments="-Dfile.encoding=UTF-8"
```

（首次构建要联网拉依赖；本机已有仓库缓存后可以加 `-o` 离线跑。）

`:80` = 管理端 API，`:81` = 用户端 API。
注意 `:81` **强依赖 Redis**：`RedisConfig` 注册了 key 过期监听器，Redis 连不上就直接启动失败、端口不会监听。

### 3. 前端

```bat
cd 面向用户              & npm install & npm run serve    REM :8080
cd ..\面向管理员前端页面   & npm install & npm run serve    REM :8081
```

两个前端**是 vue-cli 5 / webpack，不是 Vite**。改 `.vue` 之后别去 grep `js/app.js`，懒加载 chunk 名是 `js/src_views_Login_vue.js`（用户端）、`js/login.js`（管理端登录）、`js/icon.js`（管理端多个页面共享的 chunk）。

### 4. 环境变量（都有默认值，不配也能跑，功能自动降级）

| 变量 | 作用 | 不配会怎样 |
|---|---|---|
| `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL` | 智能体的大模型（OpenAI 兼容端点） | AI 浮窗走规则兜底，仍可用；撞到限流也会退到这一版并说明原因 |
| `QINIU_ACCESS_KEY` / `QINIU_SECRET_KEY` / `QINIU_BUCKET` | 图片上传（仓库里没有桶名和域名的默认值，得自己配） | 上传接口返回 `511`，并列出缺哪几个变量 |
| `MYSQL_PASSWORD` | 数据库口令 | 用本地开发默认值 |
| `REDIS_PASSWORD` | Redis 口令 | 不发送 AUTH（本机 Redis 未设 requirepass） |
| `VUE_APP_API_BASE` | 前端 API 基址 | 用 `.env.development` / `.env.production` 里的本地默认值 |
